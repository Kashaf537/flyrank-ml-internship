Refresh Opportunity Scoring: Prioritizing Content for Review

A machine-learning decision-support approach for ranking content pages that show evidence of declining search performance.

Author: Kashaf Fayyaz Lane: Refresh / Content Opportunity Scoring Date: August 2026

Abstract

This project investigates whether historical content-performance signals can help prioritize pages for potential content review. A page-level dataset was constructed from anonymized FlyRank warehouse data using historical search-performance signals such as impressions, clicks, and average search position. A transparent baseline ranking rule was compared with a Decision Tree model using the same held-out test set. Both approaches achieved a Precision@20 of 1.00 and a Precision@50 of 1.00 on the evaluation set, indicating that the highest-ranked pages in both approaches were positive cases under the defined target. The result supports using the ranking output as a decision-support queue, while the high positive base rate and single-client dataset mean that the findings should not be interpreted as evidence of causal SEO impact or universal model performance.

1. Introduction / Problem Statement

Content teams may have to review large numbers of pages while having limited editorial resources. The practical question is:

Which content pages should an editor review first for potential refresh or further investigation?

This capstone treats the problem as a ranking and prioritization task rather than an automatic content-editing system.

The system uses historical performance information to assign a score to each page. Pages can then be ordered from highest to lowest priority so that an editor can begin with the strongest candidates.

The purpose of machine learning here is not to predict Google's ranking algorithm. Instead, it is to test whether historical signals can support a more systematic review queue.

Performance Signals

The modeling dataset contains historical search-performance and query-coverage signals. The main feature groups include:

  • Recent-period impressions

  • Total impressions over the historical window
  • Visible query count
  • Rare query count
  • Rare-impression share
  • Anonymized-impression share

Data Safety

Pseudonymous client and content identifiers were used only for joins, grouping, and traceability. They were not used as numerical predictive features.

Client names, domains, URLs, private queries, credentials, and other identifying information are excluded from the public paper.

3. Methodology

Target

The target represents whether a content page belongs to the predefined declining-performance opportunity class based on its historical performance change.

The modeling dataset contains:

  • 927 positive cases
  • 453 negative cases
  • 67.17% positive-class base rate

Model

A Decision Tree classifier was used as the primary ML model. Decision Trees were selected because their learned structure is relatively easy to interpret and communicate to an editorial audience.

Baseline

A transparent baseline ranking rule was constructed using historical performance signals. The baseline provides a simple benchmark against which the learned model can be compared.

Validation

The modeling dataset was divided into training and test sets:

1,104 Training rows
276 Test rows

Both the baseline and Decision Tree were evaluated on the same held-out test set.

Leakage Controls

Target-derived fields and future outcome information were excluded from the predictive feature set. Pseudonymous identifiers were treated as grouping variables rather than predictive signals.

5. Limitations & Honest Framing

  • The current modeling sample contains only one client, so multi-client generalization could not be evaluated.
  • The positive-class base rate is high at 67.17%, so Precision@K must be interpreted alongside the base rate.
  • The Decision Tree did not outperform the baseline on the reported Precision@20 or Precision@50 metrics.
  • The target represents a defined performance-decline proxy and does not establish why performance changed.
  • The results do not establish that refreshing a page causes improved rankings, clicks, or traffic.
  • The model does not predict Google's ranking algorithm.
  • Results should be revalidated on a larger multi-client dataset before production use.

Recommended Workflow

  1. Start with the highest-ranked pages.
  2. Check the recent-versus-previous performance change.
  3. Review search visibility and average position.
  4. Investigate the underlying content before making changes.
  5. Use the model score as prioritization evidence rather than as an automatic refresh decision.

Recommended Action

Pages showing substantial observed declines in recent impressions can be placed near the top of the editorial review queue when they also have sufficient historical visibility.
